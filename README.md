# Интерфейс администратора

Админка Persona1ia. React 19, TypeScript и Vite, структура по FSD.

## Запуск

Нужен Node.js 24. В репозитории сервера установите зависимости, задайте первоначальный пароль (`npm run password:reset`) и запустите `npm run dev`. Если пароль уже настроен, сбрасывать его не нужно.

В этом репозитории:

```sh
npm ci
npm run dev
```

Админка доступна на `http://localhost:5174`. Dev-прокси пересылает `/api` на `http://127.0.0.1:3000`, сохраняя исходный Host. Для входа используется пароль владельца сервера. Тестовые данные и фиктивные показатели в интерфейс не подставляются.

## Возможности

- Лендинг: восемь типов блоков, изменение порядка, дублирование, скрытие, удаление, редактирование содержимого, изображений и кнопок
- Предпросмотр содержимого для компьютера и телефона; он не воспроизводит точное оформление отдельного приложения лендинга
- Курсы: создание и редактирование карточек, обложек, цены и видимости; удаление очищает ссылки на курс в блоках
- Медиатека: загрузка PNG, JPEG, WebP и GIF до 10 МиБ, просмотр и удаление неиспользуемых файлов
- Заказы: список тестовых покупок, поиск по загруженным записям и выгрузка CSV
- История: просмотр и восстановление версий, скачивание и импорт резервной копии
- Настройки: название, описание, контакты, ссылки и смена пароля

Правки хранятся в памяти вкладки, пока не нажата кнопка «Опубликовать». Переход между разделами их сохраняет; закрытие или перезагрузка вкладки вызывает предупреждение. Сохранение сразу обновляет лендинг и создаёт версию на сервере. При конфликте версий черновик остаётся в памяти: его можно скачать перед загрузкой актуальной версии. Скачанный черновик содержит только документ, без изображений, и не является резервной копией.

Восстановление версии и импорт копии сразу публикуют данные и требуют подтверждения. Копия содержит настройки и используемые изображения, но не заказы, пароль, сеансы и историю. Медиа, используемые любой сохранённой версией, сервер не разрешает удалять.

Сеанс хранится в HttpOnly-cookie. Пароль не сохраняется в localStorage. Если сеанс истёк, повторный вход сохраняет несохранённые правки текущей вкладки.

## Проверки

```sh
npm run typecheck
npm run lint
npm run format:check
npm test
npm run test:integration
npm run build
```

`npm test` проверяет HTTP-клиент, валидацию документа и отображение цен с учётом минимальных единиц валюты. Интеграционная проверка использует собранный `../server/dist`, создаёт отдельную SQLite-базу в памяти и проверяет реальные API. Рабочая база, пароль и запущенный сервер не меняются. Если соседний сервер не собран, интеграционный тест помечается как пропущенный; сначала выполните сборку в его репозитории.

## Развёртывание

Сборка находится в `dist`. Отдавайте её с того же HTTPS-домена, что и API, например в `/admin/`. Пути к ресурсам относительные, а маршруты разделов используют hash, поэтому размещение в подпапке не требует отдельной сборки или правил перезаписи. Настройте перенаправление `/admin` на `/admin/`. Прокси должен сохранять Host и разрешать до 64 МиБ для `/api/`, как описано в README сервера. В production авторизационная cookie требует HTTPS.

## Структура

`app` собирает навигацию, авторизацию и общий черновик. Независимые слайсы `pages` содержат сценарии своих разделов. `entities/site` описывает документ лендинга, его фабрики и проверку. `shared` содержит транспорт, общие токены, иконки и форматирование валют. Между модулями используются публичные входы; стили подключаются из их `index.ts`.
